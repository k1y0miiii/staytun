# staytun

**VPN упал — интернет тоже. Твой IP остаётся дома.**

Kill switch для VPN на macOS и Linux. Если туннель моргнул хоть на секунду,
ни один пакет не уйдёт в сеть с твоего настоящего IP.

[English version](README.en.md)

## Зачем это

VPN падает: роутер переподключился, сервер перезапустился, Wi‑Fi моргнул, ноутбук проснулся.
Система за долю секунды переключает трафик на обычный интернет, и все открытые приложения —
Claude, ChatGPT, Cursor, Gemini, Telegram — **тут же стучатся на свои серверы с твоего домашнего IP**.

Для сервисов, которые следят за регионом, это выглядит как «аккаунт прыгает между странами».
Итог — проверки, ограничения, бан.

Встроенные «kill switch» в VPN-клиентах работают на уровне приложения и часто не успевают.
**staytun режет трафик в ядре системы** (pf на macOS, nftables на Linux): всё, что идёт не через
туннель, просто не выходит наружу. Упал VPN — пропал интернет. Поднялся — всё снова работает.

## Быстрый старт

```sh
curl -fsSL https://raw.githubusercontent.com/k1y0miiii/staytun/main/install.sh | sh
```

1. Подключи VPN как обычно.
2. `staytun doctor` — проверит, что всё найдено.
3. `staytun on` — включит защиту (спросит пароль администратора).

Выключить: `staytun off`. Посмотреть состояние: `staytun status`.

## Что умеет

- **Защищает всю систему сразу** — браузер, приложения, терминал, Docker. Не нужно настраивать каждую программу.
- **Сам находит VPN-клиент**, его серверы и туннель — вписывать IP руками не нужно.
- **Понимает маршрутизацию клиента.** Если VPN пускает российские сайты напрямую (`geoip:ru`),
  staytun пускает их тоже — Госуслуги и банки продолжают работать.
- **Знает все твои серверы**, а не только текущий: переключаешься между локациями — защита не мешает.
- **Не даёт запустить** Claude Code, Cursor и другие CLI без защиты (по желанию).
- **Ничего не ломает**: правила живут до перезагрузки или `staytun off`, штатный фаервол macOS возвращается как был.
- Ни одной сторонней библиотеки — только стандартный Python 3.14. Сам staytun в сеть не ходит — только резолвит домены серверов через DNS.

## Поддерживаемые VPN-клиенты

| Клиент | Система | Что находит сам |
|---|---|---|
| **V2Box** | macOS | серверы, direct-правила (geoip, IP), geoip.dat |
| **v2RayTun** | macOS | все серверы из профилей и подписок, direct-правила |
| **Streisand** | macOS | все серверы из профилей |
| **Happ** | macOS | сервер — по живому подключению ядра (в т.ч. root-демон `happd` и версия из App Store) |
| **Hiddify** | macOS, Linux | серверы и direct-правила из конфига (экспериментально) |
| **WireGuard / AmneziaWG** | macOS, Linux | endpoint — по живому подключению; на Linux ещё и из `/etc/wireguard` |
| **Любой другой** | macOS, Linux | ручной режим: туннель находится сам, серверы — через `staytun allow add` |

Не нашёл свой клиент — работает ручной режим (ниже), а адаптер можно добавить (см. «Как добавить клиент»).

## Установка

**Требования**
- macOS 12+ или Linux с nftables (Ubuntu 20.04+, Debian 11+, Fedora, Arch).
- Python 3.14. Ставить его самому не нужно: установщик принесёт его через [uv](https://docs.astral.sh/uv)
  в отдельную папку, системный Python и Homebrew не затрагиваются.

**Одной командой** (ставит в `~/.local/bin`, без sudo):

```sh
curl -fsSL https://raw.githubusercontent.com/k1y0miiii/staytun/main/install.sh | sh
```

**Из исходников:**

```sh
git clone https://github.com/k1y0miiii/staytun && cd staytun && ./install.sh
```

**Если uv уже стоит:**

```sh
uv tool install --python 3.14 git+https://github.com/k1y0miiii/staytun
```

Обновление — та же команда установки ещё раз.

## Как пользоваться

```sh
staytun on        # включить (VPN должен быть подключён)
staytun off       # выключить
staytun status    # включено ли, через какой туннель, что пропускается
staytun doctor    # диагностика: что найдено и можно ли включать
```

Можно и с дефисами: `staytun --on`, `staytun --off`, `staytun --status`.

### Проверь, что работает

1. `staytun on`
2. Узнай IP: `curl https://ifconfig.me` — должен быть IP VPN-сервера.
3. Отключи VPN в клиенте.
4. Повтори: `curl -m 5 https://ifconfig.me`

**Правильный результат:** ошибка или таймаут. Если показался твой домашний IP — защита не работает,
запусти `staytun doctor` и создай issue с его выводом.

5. Включи VPN обратно — интернет вернётся сам. Если нет — `staytun on` ещё раз
   (бывает, что клиент поднял туннель под другим именем).

## Исключения: что пускать мимо VPN

По умолчанию мимо туннеля разрешены только:
- серверы твоего VPN (иначе он не сможет переподключиться);
- то, что VPN-клиент сам маршрутизирует напрямую (например, `geoip:ru`);
- локальная сеть: роутер, принтер, NAS.

Добавить своё — IP, подсеть или домен:

```sh
staytun allow add 203.0.113.7               # один IP
staytun allow add 198.51.100.0/24           # подсеть
staytun allow add vpn2.example.com          # домен (резолвится при staytun on)
staytun allow list                          # что добавлено
staytun allow rm 203.0.113.7                # убрать
```

Добавленное применяется сразу, если защита включена. Список хранится в `~/.config/staytun/allow.txt` —
его можно править и руками.

> **Совет.** Впиши в исключения *все* серверы своей VPN-подписки. Тогда переключение между
> локациями будет работать при включённой защите, даже если клиент не поддерживается автоматически.

## Настройки

```sh
staytun config                 # показать все
staytun set <ключ> <значение>  # изменить
```

| Ключ | По умолчанию | Что значит |
|---|---|---|
| `interface` | `auto` | Туннель. `auto` — тот, через который сейчас идёт интернет. Или имя: `utun4`, `wg0`, `tun0` |
| `clients` | `auto` | Какие клиенты учитывать: `auto`, `none` или список `v2box,happ` |
| `direct` | `yes` | Пускать мимо туннеля то, что клиент сам маршрутизирует напрямую |
| `lan` | `yes` | Доступ к локальной сети |
| `geoip` | — | Дополнительные страны мимо туннеля, например `ru,by` |
| `geoip_file` | — | Путь к `geoip.dat`, если ни один клиент его не дал |
| `protect` | `claude cursor cursor-agent` | Команды, которые не запустятся без защиты |

Примеры:

```sh
staytun set direct no          # строгий режим: вообще всё только через VPN
staytun set geoip ru           # российские IP — напрямую, даже если клиент так не умеет
staytun set interface wg0      # туннель указан явно
staytun set clients none       # только ручной режим
```

### Какой туннель выбрать

```sh
staytun interfaces
```

Покажет все VPN-туннели и отметит тот, через который сейчас идёт интернет. Обычно ничего выбирать
не нужно: `auto` берёт именно его. Явно указывать стоит, если у тебя несколько VPN одновременно.

## Не запускать программы без защиты

Добавь в `~/.zshrc` или `~/.bashrc`:

```sh
eval "$(staytun shell-init)"
```

Теперь `claude`, `cursor` и `cursor-agent` откажутся стартовать, если защита выключена или VPN упал.
Список меняется так: `staytun set protect "claude cursor gemini codex"`. Запустить в обход: `command claude`.

Разово: `staytun run claude` — запустит, только если защита активна.

## Частые вопросы

**После включения пропал интернет.**
Значит, VPN сейчас не подключён или переподключился под другим именем туннеля. Подключи VPN и выполни
`staytun on` ещё раз. Аварийно выключить: `staytun off`. Перезагрузка тоже всё сбрасывает.

**`staytun on` отказывается: «VPN ходит к своему серверу мимо туннеля».**
Это защита от ситуации выше. Перед включением staytun смотрит, куда VPN-клиент подключается в обход
туннеля. Если ни один из этих адресов не в исключениях, значит сервер VPN неизвестен и защита отрезала бы
сам VPN. Проверь, что показанные IP — твой VPN-сервер, и выполни `staytun on --auto`: staytun запомнит их.

**Не открываются российские сайты.**
staytun пускает напрямую только то, что твой клиент маршрутизирует напрямую *по IP*. Правила по доменам
(`geosite:category-ru`) фаервол проверить не может — такие сайты на зарубежных CDN будут заблокированы.
Решение: `staytun set geoip ru` или добавь нужный адрес через `staytun allow add`.

**Поменял сервер в VPN-клиенте — интернет не появился.**
Новый сервер ещё не в исключениях. Выполни `staytun on` (найдёт его заново) или заранее добавь
все серверы подписки: `staytun allow add ...`.

**Happ / WireGuard: «сервер не найден».**
Их серверы видны только у работающего подключения. Подключись и выполни `staytun sync`.
staytun запомнит адрес на будущее. Ядро Happ работает от root (через демон `happd`), поэтому
`staytun doctor` без sudo его не видит — `staytun on` и `staytun sync` смотрят уже под sudo.

**Защита после перезагрузки?**
Сбрасывается — это сделано специально, чтобы staytun никогда не оставил тебя без интернета навсегда.
Если программы стартуют вместе с системой (Claude, Cursor, Telegram), убери их из автозагрузки или
первым делом выполняй `staytun on`.

**У меня свой /etc/pf.conf (macOS).**
Пока staytun включён, используется штатный набор Apple + правила staytun. Твои правила вернутся после
`staytun off`.

**Docker / виртуалки на Linux?**
Защищены: staytun фильтрует и трафик хоста, и пересылаемый (forward).

**Что staytun НЕ делает.**
Он защищает только от утечки IP. Часовой пояс, язык системы, отпечаток браузера и DNS-запросы
к провайдеру (без VPN) — это другие истории.

## Как это устроено

```
приложение ──► ядро ──┬─► VPN-туннель (utun / wg / tun) ──► интернет      ✓
                      ├─► VPN-сервер напрямую (handshake) ──► интернет   ✓
                      ├─► direct-маршруты клиента, LAN                    ✓
                      └─► всё остальное                                   ✗ drop
```

- **macOS:** pf. Главный набор правил заменяется копией штатного `/etc/pf.conf` плюс правила staytun.
  Блокировка стоит раньше якорей Apple, `state-policy if-bound` не даёт старым соединениям уйти через Wi‑Fi,
  pf включается через токен, не ломая другим программам их правила.
- **Linux:** nftables, отдельная таблица `inet staytun`, атомарная замена, цепочки output и forward.
- Серверы берутся из конфигов клиентов (это VPN-серверы — пускать к ним напрямую безопасно).
  Direct-правила — только у запущенного клиента. Живые соединения читаются только у Happ и WireGuard,
  где процесс не ходит никуда, кроме своего сервера.
- Состояние хранится в `/var/run/staytun.state` (macOS) или `/run/staytun.state` (Linux), его пишет root.

Посмотреть правила, ничего не применяя: `staytun rules`.

## Как добавить клиент

Адаптер — это класс в [`src/staytun/clients.py`](src/staytun/clients.py). Для клиентов на xray-core
обычно достаточно указать пути:

```python
class MyClient(XrayClient):
    id, title, platforms = "myclient", "MyClient", ("darwin",)
    homes = ("~/Library/Group Containers/group.com.example.myclient",)  # где лежат данные
    procs = ("MyClient.app/Contents/PlugIns",)                          # как узнать, что запущен
    configs = ("profiles/*.json",)                                      # все серверы
    active = ("current.json",)                                          # текущий конфиг с routing
```

Добавь его в список `ALL`, тест в `tests/` — и присылай pull request.
